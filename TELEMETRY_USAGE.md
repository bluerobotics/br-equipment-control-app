# Telemetry System Usage Guide

## Overview

The telemetry system provides a centralized, autogenerated approach to managing device telemetry data. All telemetry variables are defined in `telemetry.json` and automatically generate the necessary C++ code for the embedded device.

## Architecture

### Files Generated

For each device (e.g., fillhead), the following files are autogenerated:

1. **`telemetry.h`** - Telemetry structure and function declarations
2. **`telemetry.cpp`** - Telemetry construction and transmission implementation
3. **`responses.h`** - Response message prefixes and status codes

### Key Features

- **Centralized Definition**: All telemetry fields defined in one place (`telemetry.json`)
- **Type-Safe Structure**: Complete `TelemetryData` struct with proper C types
- **Automatic Message Construction**: Functions to build and send telemetry messages
- **Consistent Format**: All telemetry follows the format `DEVICE_TELEM: field1:value1,field2:value2,...`

## Usage in Embedded Firmware

### 1. Include the Header

```cpp
#include "telemetry.h"
```

### 2. Declare Telemetry Data Structure

Create a global or static instance of the telemetry data structure:

```cpp
TelemetryData g_telemetry;
```

### 3. Initialize Telemetry

Initialize the telemetry structure with default values at startup:

```cpp
void setup() {
    // Initialize telemetry with default values from telemetry.json
    telemetry_init(&g_telemetry);
    
    // ... rest of setup code
}
```

### 4. Update Telemetry Fields

Update individual fields as your application runs:

```cpp
void loop() {
    // Update state fields
    g_telemetry.fillhead_state = SYSTEM_STATE_BUSY;
    g_telemetry.injector_state = MOTOR_STATE_HOMING;
    
    // Update sensor readings
    g_telemetry.temp_c = read_temperature();
    g_telemetry.vacuum_psig = read_pressure();
    
    // Update motor status
    g_telemetry.injector_torque = motor.GetTorque();
    g_telemetry.injector_homed = motor.HlfbState() == HLFB_HOMED;
    
    // Send telemetry at regular intervals
    if (millis() - last_telem_time > TELEM_INTERVAL_MS) {
        telemetry_send(&g_telemetry);
        last_telem_time = millis();
    }
}
```

### 5. Send Telemetry

Send telemetry using the built-in function:

```cpp
// Automatically builds and sends the complete telemetry message
telemetry_send(&g_telemetry);
```

Or build the message manually:

```cpp
char buffer[512];
int len = telemetry_build_message(&g_telemetry, buffer, sizeof(buffer));
if (len > 0) {
    Serial.println(buffer);
    // Or send via UDP, etc.
}
```

## Complete Example

```cpp
#include "ClearCore.h"
#include "telemetry.h"
#include "responses.h"

#define TELEM_INTERVAL_MS 100

TelemetryData g_telemetry;
uint32_t last_telem_time = 0;

void setup() {
    // Initialize serial
    ConnectorUsb.Mode(Connector::USB_CDC);
    ConnectorUsb.Speed(9600);
    ConnectorUsb.PortOpen();
    
    // Initialize telemetry with defaults
    telemetry_init(&g_telemetry);
    
    // Send info message
    ConnectorUsb.Send(STATUS_PREFIX_INFO);
    ConnectorUsb.SendLine("System initialized");
}

void loop() {
    // Update telemetry fields from your application state
    g_telemetry.fillhead_state = get_system_state();
    g_telemetry.injector_torque = get_motor_torque();
    g_telemetry.temp_c = read_temperature();
    // ... update other fields
    
    // Send telemetry at regular intervals
    if (millis() - last_telem_time >= TELEM_INTERVAL_MS) {
        telemetry_send(&g_telemetry);
        last_telem_time = millis();
    }
}
```

## Telemetry Message Format

The generated telemetry message follows this format:

```
FILLHEAD_TELEM: fillhead_state:0,injector_state:1,inj_valve_state:2,...
```

- **Prefix**: `DEVICE_TELEM: ` (e.g., `FILLHEAD_TELEM: `)
- **Fields**: Comma-separated key:value pairs
- **Keys**: Field names from `telemetry.json`
- **Values**: Current values formatted according to type and precision

## Modifying Telemetry

To add, remove, or modify telemetry fields:

1. Edit `devices/<device_name>/telemetry.json`
2. Run the code generator:
   ```bash
   python3 generate_all_headers.py
   ```
   Or use the GUI: `Tools > Code Generator`

3. The `telemetry.h` and `telemetry.cpp` files will be automatically regenerated

## TelemetryData Structure

The `TelemetryData` struct contains all telemetry fields with proper C types:

```cpp
typedef struct {
    int32_t      fillhead_state;           // Integer state values
    float        injector_torque;          // Float sensor readings
    bool         motors_enabled;           // Boolean flags
    // ... all other fields from telemetry.json
} TelemetryData;
```

### Type Mapping

| JSON Type | C Type    | Notes                           |
|-----------|-----------|----------------------------------|
| `int`     | `int32_t` | 32-bit signed integer           |
| `float`   | `float`   | IEEE 754 single precision       |
| `bool`    | `bool`    | C++ boolean (C99 stdbool.h)     |

## Benefits

1. **Single Source of Truth**: `telemetry.json` defines all fields
2. **Type Safety**: Compiler catches type errors
3. **Consistency**: Same format across all devices
4. **Easy Maintenance**: Add/remove fields without manual code changes
5. **Documentation**: Auto-generated comments from JSON help text
6. **No Manual String Formatting**: All message construction is automated

## Integration with GUI

The Python GUI automatically parses telemetry messages using the same `telemetry.json` schema, ensuring perfect synchronization between embedded firmware and the control application.
