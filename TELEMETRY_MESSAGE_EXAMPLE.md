## Message Format Breakdown

### Structure
```
PREFIX: key1:value1,key2:value2,key3:value3,...
```

### Components

1. **Prefix**: `DEVICE_TELEM: ` (e.g., `FILLHEAD_TELEM: `)
   - Identifies the device and message type
   - Allows GUI to route message to correct parser

2. **Key-Value Pairs**: `key:value`
   - Keys are exact field names from `telemetry.json`
   - Values formatted based on type:
     - `int` → decimal integer
     - `float` → decimal with precision from JSON
     - `bool` → 0 or 1

3. **Separator**: `,` (comma)
   - Separates each key-value pair
   - No trailing comma on last field

## Precision Examples

### From telemetry.json
```json
{
    "temp_c": {
        "type": "float",
        "precision": 1
    },
    "injection_cumulative_ml": {
        "type": "float",
        "precision": 2
    }
}
```

### In Generated Code
```cpp
// temp_c with precision 1
pos += snprintf(buffer + pos, buffer_size - pos, "%s:%.1f,", 
                TELEM_KEY_TEMP_C, data->temp_c);

// injection_cumulative_ml with precision 2  
pos += snprintf(buffer + pos, buffer_size - pos, "%s:%.2f,", 
                TELEM_KEY_INJECTION_CUMULATIVE_ML, data->injection_cumulative_ml);
```

### Output
```
temp_c:75.3,injection_cumulative_ml:150.25
```

## Parsing in Python GUI

The GUI automatically parses these messages using the same `telemetry.json`:

```python
def parse_dynamic_telemetry(msg, device_name, schema, gui_refs):
    prefix = f"{device_name.upper()}_TELEM:"
    payload_start = msg.lower().find(prefix.lower()) + len(prefix)
    payload = msg[payload_start:].strip()
    
    # Parse: fillhead_state:1,injector_state:2,...
    parts = dict(item.split(':', 1) for item in payload.split(',') if ':' in item)
    
    # Map to GUI variables using schema
    for key, value in parts.items():
        if key in schema:
            gui_var = schema[key].get('gui_var')
            # Update GUI variable...
```

## Manual Message Building (Old Way)

### Before Auto-Generation
```cpp
char buffer[512];
snprintf(buffer, sizeof(buffer), 
    "FILLHEAD_TELEM: fillhead_state:%d,injector_state:%d,temp_c:%.1f,torque:%.1f,...",
    state, inj_state, temp, torque, /* 17 more fields! */);
Serial.println(buffer);
```

**Problems:**
- Error-prone with many fields
- Hard to maintain when adding/removing fields
- Easy to mess up formatting
- No type safety

### After Auto-Generation
```cpp
g_telemetry.fillhead_state = state;
g_telemetry.injector_state = inj_state;
g_telemetry.temp_c = temp;
g_telemetry.injector_torque = torque;
// ... update other fields

telemetry_send(&g_telemetry);  // Handles everything!
```

**Benefits:**
✅ No manual string formatting
✅ Compiler checks types
✅ Automatically maintains all fields
✅ Single function call

## Conclusion

The auto-generated telemetry system produces consistent, well-formatted messages with zero manual string formatting. All formatting logic is automatically generated from `telemetry.json`, ensuring perfect synchronization between the embedded device and the GUI.
